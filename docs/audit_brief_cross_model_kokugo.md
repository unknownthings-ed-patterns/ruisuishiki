## 0. 監査者への 3 つの約束（数学版と同じ・最重要）

1. **ファイルを編集しない。報告だけする。** git 操作もしない
2. **すべての指摘に「証拠」を付ける**——`ファイル:行番号`＋該当文字列の引用。証拠の無い指摘は採用できない
3. **推測で断定しない**。確かめられなかったものは「未確認」と正直に書く

## 1. トリアージ（数学版と同じ）

- **Blocker**＝学習者に誤りが届く（choice の正解が成立しない／別の選択肢も正解になってしまう／問題文・ヒントが答えを先に言っている／保護中作品の本文が混入している）
- **Major**＝設計原則（7条件・G1〜G12・言い換え規律）に反する
- **Minor**＝表現・誤字・好み
- **S**＝欠陥ではないが質を上げる提案（別枠・書式は §3）

**Blocker/Major は歩く前に直す。Minor は歩きながら。**

## 2. 監査の観点（この順で。1 と 2 が本命）

### 観点1：choice を自力で解く（★最重要）

`answerIndex` を見る前に、問題文と教材（mentorTexts）だけで自分で解く。国語は数学より**答えの一意性が脆い**——ここが別モデルにしか埋められない層。

- 正解селが成立しないなら Blocker
- **他の選択肢も「正解だ」と言い張れてしまう**なら Blocker（例：なぞなぞ詩の3択で、比喩の列が別の答えも絞り切れていない／「どの行がきめて」で複数の行が同格）
- 問題文・L1・L2 が答えを先に言っていたら Blocker（「答のみで自得」が壊れる）
- choice の判定根拠が「ルール」でなく「好み」になっていないか（G2——「出会っている」「裏切っている」「つながっている」の判定が、提示されたきまりから一意に出るか）

### 観点2：教材と本文の内部整合

- L3 が語る教材の中身（比喩の数・行の内容・順序・音）が、**mentorTexts の実物と一致しているか**（例：「六つのひゆを重ねた」と言うが実物は五つ、等）
- 「Step◯でやった△△」の参照が実際の step と合っているか。`compareWithStepId` は自然か
- 観点リスト（viewpointLists）の文面と、系列が実際に発見させる内容が合っているか
- 日記の reorder（たまごやき）：**正順が本当に物理的に一意か**（別の順でも筋が通ってしまわないか）

### 観点3：ヒント3層の規律——機械 audit に見えない層

`audit_hints_kokugo.py` は正規表現なので、以下は**目でしか見えない**（handoff §3 の既知の限界）：

- **L1 が「日本語で言い換えた解説」になっていないか**（技法名を避けていても、手順や答えの方向を教えていたら違反）
- **L2 が差異1つの名指しか**（L1 の言い換えになっていないか）
- **L3 に代筆（完成作品の提示）が紛れていないか**（G10・最上位禁止条項。機械は「かぎかっこ内のかな連続」しか検出しない。**地の文に紛れた完成例・そのまま使える一行の提供**を見てほしい——ただし「模範文側の作り方の言語化」は仕様）
- 言い換え語彙表（handoff §1＋各背骨）の漏れ——L1/L2 に技法名の同義語が素通りしていないか

### 観点4：G1〜G12 の目視層

とくに **G1**（基準・観点の先出し——読み比べの前に「いいところ」を教えていないか。中心の問い・問題文・L1/L2 が step 後半の発見をネタバレしていないか）と **G2**（機械が「正解」を発明——見立てや良し悪しに正解を作っていないか。判定はルールのみ、が守れているか）。

### 観点5：教材（作品）の質——お手本として立つか

自作教材はお手本＝系列の天井。学習者としてまっさらに読んで：

- なぞなぞ詩：**当たるか**（比喩の交点が一つに絞れるか・難しすぎ/易しすぎないか）
- 一口お笑い：**声に出して笑いが立つか**（韻のリズム・オチの切れ）
- 視覚詩：**形が立つか**（縦書き・行＝列・右から左、を頭の中で組んで見る）
- お話・日記：筋の一貫・小2の語彙（日記）・表記（日記は段落1字下げ・「」前後改行が**仕様**）
- 惜しい教材は S に（書式は §3）

### 観点6：権利・出典表記の整合

- **保護中作品の本文混入ゼロの確認**：白谷明美の本の作例（きゅうり・とけい・ごみばこ・数字の5・です・ちり・さい・たね・たい・ちゅう・なし）／岩井の教え子の作品（本・靴下・ペン・ハサミ・買って・すぎ）／内田麟太郎・新国誠一・寺山修司・WCW戦前作の本文が、教材・ヒント・作家の風景のどこにも入っていないか
- sourceNote の主張が正しいか（PD 判定の年号・licensed の記載・「構成は借り本文は借りていない」が実態と合うか）
- 山村暮鳥「風景」の本文が青空文庫（作品ID 52348・新字旧仮名「おしやべり」）と一致しているか

### 観点7：S（質を上げる提案・別枠）

物差しは**自分の好みではなく**、`CLAUDE.md` 国語版お手本7条件と G1〜G12。1系列につき最大2件・出ない系列は「S なし」・「歩く前」5件以内をサマリ冒頭に・良かった点も3〜5件。
**代案の文案を書くなら、その文案が系列の規律（韻・言い換え表・G10・小2語彙）を満たすか自分で確かめてから書く。確かめられないなら診断と制約だけ書いて、文案はメインに委ねる**（数学版 §6 2-a-2 の教訓）。

### 観点8：4系列の比較所見（★今回だけの特別依頼）

この監査のあと、メインが**詩4系列（①〜④）の比較から「詩版お手本条件」を抽出**する（俳句7条件と同じ工程）。その材料として：

- **4系列に共通して効いている不変項**（構造・ヒントの型・教材の作り・step 配列——「どの系列も◯◯している」）
- **系列ごとに揺れている点**（①はやっているが③はやっていない、等。揺れが欠陥なのか多様性なのかの見立ても）
- **俳句7条件（CLAUDE.md）のうち、詩ではそのまま通用しないと感じた条項**

を「**比較所見**」として1節にまとめてほしい。ここは指摘ではなく観察でよい。**外の目で見た不変項こそ、メインの内側の基準に無い抽出材料になる。**

## 3. ユニット固有の注意（仕様を欠陥と誤解しないために）

| 仕様 | 中身 |
|---|---|
| creation step は判定しない | 作品に正解を作らない（G2）。`meterTarget: []`・selfChecklist は自己点検 |
| 図マーカーは宣言のみ／なし | 国語プレーヤーは figureMarker を描画しない（既知）。視覚詩・なぞなぞ詩・一口お笑いは「作品自体が図」の判断で宣言もなし |
| 「オチ」「ひゆ」「スローモーション」 | 裁定済みの語——「オチ」は問題文・L2 可（子どものお笑い語彙）。「ひゆ」「スローモーション」は問題文・L3 のみ |
| 「とって」の空行 | オチの前の間（ま）。作者（岩井）の確定版。欠落ではない |
| 日記の表記 | 段落頭1字下げ・「」会話文の前後改行・続け書き＝表記規範（先生指示）。文カード素材（たまごやき・ねるまで・アイス・すきま前後）だけ1文単位＝課題の性質上の仕様 |
| 八百屋日記が常体 | 大人の実物（本物に会う）としての仕様 |
| 教材はドラフト一字不変 | 教材の正は vault（リポ外）。**教材の文面そのものへの変更提案は S で**（Blocker は混入・不整合のみ） |
| 正答率を出さない | G8。あしあと表示は仕様 |

## 6. 監査のあと（メインの手順・数学版 §6 と同じ）

1. Blocker/Major を1件ずつ追試（証拠の行を開いて自分で確かめる）→採用分だけ直す・却下は理由を残す
2. S は追試＋コスト添えで先生に一覧で裁定を仰ぐ（直さない判断も同じくらい正しい）
3. 修正後は機械4点→commit/push→デプロイ確認
4. **比較所見（観点8）を詩版お手本条件の抽出材料に合流させる**——今回の監査のいちばんの目的
5. 「メインの検収が構造的に見落とした層」を CLAUDE.md か handoff に還流する
