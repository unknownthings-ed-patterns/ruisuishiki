## 1. 確定した方針（岩井先生と合意）

### カタログ構造 = 領域縦断

学年ごとに領域を切り替える教科書配列ではなく、**一つの領域を学年をまたいで連続した系列群にする**（例：かけ算の意味→九九→わり算→筆算→小数の乗除→分数の乗除→正負の乗法(中1) を一本の鎖に）。

**理由（エンジンの定義から出る）**：

- ruisuishiki の中核は「比較を基盤とする近転移エンジン」（比較の指さし・一度に差異1つ）。系列の鎖が長く続くほどエンジンが強く働く。学年切り替え配列は鎖を年4回切り、「前題」が1年前に遠ざかる
- 縦断にすると**学年の切れ目が「質的変化ステップ」に変わる**。接続点がそのままオペレータ（同・逆・＋α・質的変化）で記述できる
- 胚細胞モデル（中心の問い設計の基準）の本家＝ダヴィドフのカリキュラムは、まさに一領域の胚細胞概念を数年かけて連続展開する設計。理論部品がもともと縦断型と同型
- ruisuishiki は自走型なので、学校と並走する歩行は妨げられない（学校でやっている単元の該当地点から鎖に入ればよい。「一歩手前と一歩先」が同じ鎖の上に見える利点もある）

### 混合（interleaving）は背骨ではなく復習層に置く

学年混合配列の学習科学的効能（弁別・長期保持）は捨てない。ただし受け皿は **M-6 混合復習**（パタン重ね合わせ計画・保留中）。

- **背骨（カタログ・系列の鎖）＝縦断** — 習得は比較の鎖で進む
- **復習層（混合復習）＝領域横断で混ぜる** — 「どの文型か」の見分けと忘却への抗い

学校は時間割の制約で一つの配列に両方を兼ねさせるしかないが、ソフトウェアは層を分けられる。これが学校に対する構造的優位点。

### 領域の枠組み（用語注意）

- 中学（現行指導要領）：**A 数と式（方程式を含む）・B 図形・C 関数・D データの活用**。「資料の活用」は旧称
- 小学：**A 数と計算・B 図形・C 測定(1〜3年)/変化と関係(4〜6年)・D データの活用**
- 束ね方を「現行4領域に揃える」か「体系数学式に方程式を独立させる」かは**背骨設計時の判断**（未決）

## 3. 縦断設計の注意点（背骨設計時に必ず反映）

1. **領域間の依存を明示する** — 縦断は「領域が独立」という嘘をつきやすい。関数の鎖の途中には方程式の解法が要り、図形の計量には計算が要る。系列メタデータに「橋」（前提：◯◯領域の系列△△）を持たせて鎖を渡る導線を作る
2. **縦断＝加速ではない** — ローフロアの原則（Mild は具体操作・身体活動で全員が入れる。memory `task-low-floor`）を各接続点で維持。特に小学の鎖では抽象化の一歩ごとに具体の床を張り直す
3. **領域によって鎖の太さが違う** — 数と式・方程式・関数は文型の鎖が長く太い＝主戦場。図形（特に証明）とデータの活用は文型抽出が弱く鎖が短い。全領域を同じ密度で縦断化しない。**A 領域（数と式／数と計算）から作る**

## 4. 開発開始のタイミングと準備（岩井先生の計画・2026-08-05 時点）

- **体系数学をこれから入手して試読**（問題の見せ方・図・導入の景色の資料共有のため）
- **職場の後期（教科書下巻の配布後）に全学年の算数教科書が手元に揃う** → 小学算数の手ざわり素材はそこから
- タイミングの良い時に小学算数・中学数学それぞれ開発開始。開始の GO は岩井先生

### 開始時の手順（推奨）

1. 新セッションはまず本ファイル＋ memory（`ruisuishiki-core-principles`・`mirror-best-existing-series`・`session-start-audit` の表）を読む
2. **最初の一歩＝A 領域 1 本で単元鎖の抽出**（東書細案の内容コードで小1〜小6（または中1〜中3）の A 領域単元を鎖に並べ、接続点をオペレータで記述した一覧を作って岩井先生に見せる）
3. 束ね方の裁定（現行4領域どおりか・方程式独立か）を岩井先生に仰ぐ
4. 背骨設計は既存条件 C1〜C14（`docs/backbone_design_handoff.md`）＋お手本7条件＋Q1〜Q7（`docs/quality_bar_fable_2026-07-17.md`）に従う。分担は 素材消化=Opus／背骨=Fable（不在時 Opus 代行）／裁定=先生／実装=Opus
5. 系列実装のたびに、該当単元の教科書見開き写真（＋体系数学の該当箇所）を共有してもらう
