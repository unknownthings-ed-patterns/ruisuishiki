# 数学実践本 第1弾『ruisuishiki数学ⅠA』設計メモ v0.1（Fable・2026-08-29／裁定 2026-08-29）

国語実践本（『読み書き教育における類推的学習 発展編』・23章・v0.13時点）の本づくりで確立した型を、数学版 ruisuishiki に写像するための設計文書。**実行手順とCursor用プロンプトは `docs/book_math1a_実行指示書_cursor.md`**（対で読む）。書名と着手前裁定は §7。

## 0. なぜ本を作るか（二方向設計・実測の根拠）

- 本↔サイトの往復は国語本で実測済み：独立監査 約250件のうち約80件がサイトに還流（Blocker級の教材誤り含む）。先生の通読検収からも教材の足場が複数回改善された。
- 原理＝**本化は「直線化テスト」**。サイトは順序自由・UI付きで歩けるため、(a)系列間の依存順の乱れ (b)UI依存の語り（メーター・判定・入力） (c)表示依存（画面上の位置を指す言い方） (d)選択肢とヒントを通しで読んだときの答え漏れ、が隠れる。一本の線に並べて通読すると全部あぶり出される。数学版でも同種の発見がほぼ確実。
- もう一つの意味：**戸田『推理式指導算術』（1930）はそもそも本だった**。本→サイト→本で原型に帰る。「答のみで自得」は紙と鉛筆で最もよく働く。

## 1. 分冊構成

- **第1弾『ruisuishiki数学ⅠA』・第2弾は数ⅡB帯**（科目帯切り。現在コンテンツが網羅的にある範囲と一致・読者の学年帯とKDPの棚にも自然）。読者宛て＝学習者本人が主・先生が従。副題は付けない。
- 算数・中学数学・数ⅢC・大学数学は未完成のままでよい——**「育つ本」モデル**（国語本と同じ）：終章に「未完の地図」を置き、系列が育ったら版が上がる。完成を待たずに刊行する。
- 『ruisuishiki数学ⅠA』の収録単元と順序の**正は `frontend/src/lib/seriesCatalog.ts`**（池田洋介『入門問題精講』の章順ベース＝memory/CLAUDE.mdの既定方針）。カタログ上の数Ⅰ・Aは topicGroup＝数と式・関数と関数のグラフ・三角比・場合の数・確率・集合と論理・データの分析・図形の性質・整数の性質（正確な部立てはフェーズ0でカタログから機械的に確定する。目分量で系列70本前後＝国語本の約3倍）。設計メモ旧稿の「2次関数」はカタログ正式名「関数と関数のグラフ」に合わせる。
- **部＝単元、章＝系列**（国語本と同じ対応）。

## 2. 章の器（国語本の型の数学への写像）

国語本の章構成をそのまま流用する。差分だけ記す。

```
中心の問い
第一歩〜第N歩（歩=exercise/comparison）
  問題（KaTeX数式）＋（図版）
  ＊　　＊　　＊
  ヒント1（比較の指さし）
  ヒント2（差異1つ）
  ヒント3（完全worked example＝答えまで）
書く番に相当するもの＝「作る番」（作問stepがある系列のみ）
公式の景色（derivation。中心の問い→本文→もっと深く→問いに戻ると）
出典
```

- **答えの置き方（確定）**：ヒント3に答えが含まれる現行構造をそのまま生かし、**加えて巻末に「答え一覧」**（章・歩番号→答えのみ）を置く。ヒントを見ずに答え合わせしたい読者のため＝戸田の「答のみ」の再現。
- **判定エンジンの翻訳**：サイトの数値判定（TOL厳密一致）・solutionSet は本にはない。問題文の「〜を入力してください」等の**UI語は全て語り直す**（「〜を求めよう」）。これは生成器が機械置換＋監査で拾う。
- **[用語]リンク（確定）**：本文は素文字化（国語本と同じ）。辞書の再録はv1では行わず、序章と付録で「ことばの辞書はサイトで引ける」と案内（分量爆発の回避）。
- **図（figureMarker）（確定）**：教材の図はサイトのReact/SVGマーカーが正。**サイト掲載分すべて**を収録する（Step1＋質的変化に限定しない）。**サイトに図版エクスポート用ページ（例 /figure-export?marker=...）を新設し、Chrome headless で撮影→PNG** という一般化を行う（国語本 make_figures.py の方式。--force-device-scale-factor=2・PILで白トリム＋枠）。「図は答えを書かない」原則はそのまま。エクスポートページを本番ビルドに含めるかは未決（P2。含めないなら dev サーバ専用でよい）。
- **語りの量**：無口版が標準（国語本の裁定）。数学は問題・ヒント・derivationがすでに読者向けの文章なので、章あたりの追加語りは国語本より少なくてよい＝量産向き。

## 3. 組版（横書き）

- **横書きEPUB**（数式のため。国語本の縦書きパイプラインは使わない）。page-progression=ltr・writing-mode指定なし。
- **数式**：原稿は `$...$`（pandoc math）のまま → `pandoc -t epub3 --mathml` → **`cjk_math_filter.py`**（第1巻で確立：KindleのMathMLは日本語入り数式を豆腐化する→数式内の日本語を退避する既存フィルタ。`個人/book-vol1/06_export/` と `book-kenron/06_export/` に実績あり。コピーして使う）。
- HTML並出（検収のコピペ用・国語本の教訓）：同じ原稿から `pandoc --standalone --embed-resources --mathml`。
- 検査：`etrack/check_epub.py`（XHTML/OPF妥当性）＋数式専用の機械検査（$の対応・数式内日本語の残り・KaTeX固有記法のpandoc非互換チェック）をフェーズ1で生成器と同時に作る。
- 実機確認の教訓：**ビルド成功と実機で読めることは別**。見本章の段階で一度 Kindle/Apple Books 実機を通す。

## 4. 権利

- 数学の教材は全て自作（設計者作・値はオリジナル）＝国語本のようなPD/引用の処理は不要。
- 出典は「構成は借りる・値はオリジナル・クレジットは正確に」（memory: copyright-credit-vs-copy）。池田本・戸田本のクレジットを序章と各部でこれまでの書式（APA風＋「— 」注記）どおりに。

## 5. 監査（直線化テスト）の観点セット

国語本の監査で有効だった観点の数学版。監査は**報告のみ・全指摘に行番号と引用**・部ごとに1面ずつ：

1. 誤字脱字・不自然な日本語
2. **答えの漏れ**：問い・ヒント1・2に答え/解法が出ていないか（L1=指さしのみ・L2=差異1つの規律）
3. **参照整合**：「Step N」等サイト呼称の残り／「前の系列で」の依存順が本の読み順と一致するか／宙ぶらりん参照（ヒストリーに出していない式を指す）
4. **UI語の残り**：入力・判定・メーター・タップ・ボタン・「このページ」
5. **数式**：$対応・数式内日本語・表示崩れ候補・値の検算（本文が書いた計算の内訳の和＝quality_bar層7）
6. **教材とヒントの一致**：ヒントが言う値・図の内容と実物の突き合わせ（機械で確かめたと書いた検査そのものが盲点＝quality_bar層10）
7. 図版：答えを漏らしていないか・発見を漏らしていないか（層8）

## 6. 工程の見取り図（詳細は実行指示書）

P0 章立て確定（カタログ→部・章一覧）→ P1 生成器＋機械検査（新規開発・最大の山）→ P2 図版エクスポート機構 → P3 見本章2本→岩井検収→**型の凍結** → P4 量産（単元ごと）→ P5 監査（部ごと・順次）→ P6 修正適用＋還流（ts先行→本再生成）→ P7 統合・ビルド・岩井通読 → P8 凍結v1.0→表紙→KDP。

- **Cursor体制（〜9/25）の現実的な着地目標＝P0〜P3（型の凍結）＋できれば最初の1〜2単元**。量産以降はCursor継続でもClaude復帰後でも接続できる。
- 教材の正は常に ts。**本づくりで見つけた教材の欠陥は ts を先に直し（検査→push→デプロイ確認）、本は再生成**——国語本で確立した還流の順序。

## 7. 岩井裁定（2026-08-29 確定）

着手前5件は確定。チャット履歴ではなくこの節が正。

1. **書名**＝『ruisuishiki数学ⅠA』。副題なし。読者宛て＝学習者本人が主・先生が従。
2. **巻末「答え一覧」を置く**（章・歩番号→答えのみ。ヒント3の答えは現行どおり残す）。
3. **辞書**＝v1は本文の `[用語]` を素文字化＋序章・付録でサイト案内のみ。辞書本文の再録はしない。
4. **図版**＝サイト掲載の figureMarker すべて（Step1＋質的変化に限定しない）。図が答えを書いていないかは撮影後に目視検収。
5. **作業ディレクトリ**＝ローカル `~/book-math1a/` に git init・非公開。iCloud回避。有料販売物の本文を公開リポジトリに置かない。設計文書だけこの `docs/` に置く。

残件（P0の前には不要）：

- P2：図版エクスポートページ（`/figure-export`）を本番ビルドに含めるか。含めないなら dev サーバ専用。
- P0：カタログから拾った橋渡し系列・`tertiary`（統計・データ分析）等は「裁定待ち」欄に分けて提示。
